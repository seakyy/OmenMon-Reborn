### 🎨 Graphical Fan Curve Editor (PR #242)

- **Interactive GDI+ Fan Curve Canvas (`GuiFanCurveCanvas.cs`):**
  - Edit multi-point fan curves on an interactive graph instead of writing `<FanProgram>` XML entries by hand.
  - Rendered **step-wise** rather than as straight segments to accurately match the runtime floor lookup behavior of `FanProgram.GetTemperatureLevel`.
  - Supports separate curves for CPU and GPU fans, with live temperature tracking markers.
  - Intuitive editing: click to add points, drag to reposition, delete key to remove, and keyboard arrows for 1 °C / 1 fan level micro-adjustments.
- **Profile Management Dialog (`GuiFormFanCurve.cs`):**
  - Open via tray menu: **Fan → Fan Curve Editor...**
  - Create, rename, delete, and save custom fan profiles directly from the UI.
  - **Live Preview:** Ticking "Run preview" applies the edited curve to hardware immediately without blocking background monitoring.
  - **Freeze Guard Integration:** Automatically limits maximum writable levels on freeze-risk models (`FanArray.HasMaxFanFreeze`), with an explicit confirmation override gate (`GuiOp.ConfirmMaxFanIfRisky`).
- **Mathematical Parity Test Suite (`FanCurveTests.cs`):**
  - 356 lines of unit tests verifying complete parity against runtime floor lookups, boundary clamping, and serialization round-tripping.

### 🛡️ Safety Guards & Stability Fixes

- **PAGE_FAULT_IN_NONPAGED_AREA (0x50) BSOD in win32kfull BitBlt (Fixes #250):**
  - Resolved a critical race condition where `User32.DestroyIcon` was invoked before the new icon handle was assigned to `NotifyIcon`. When Explorer / DWM performed `BitBlt` on the tray icon simultaneously, `win32kfull!DEVLOCKBLTOBJ::bDisposeTrgDco` faulted on the freed handle.
  - The new `HICON` is now created and set first, then the previous handle is cleanly destroyed.
  - Wrapped dynamic icon rendering in exception traps to safely handle display sleep, screen lock, and D3D exclusive fullscreen transitions.
  - Implemented `IDisposable` on `GuiIcon`.
- **HP OMEN 15 2020 (`878A`) RTMP Sensor & EC Lockup Guard (PR #242):**
  - Fixed 0 °C CPU temperature reporting: on board `878A`, EC `0x57` (`CPUT`) reads 0 °C while the actual package thermistor lives at EC `0x58` (`RTMP`). Mapped via native XML preset (`TempCpuReg = 88`).
  - Added `878A` to `FanArray.HasMaxFanFreeze` to prevent 100% duty cycle Embedded Controller lockups.
- **Baseboard Serial Number Privacy Redaction (Fixes #228):**
  - Hardware reports from `-Probe`, `-Diag`, and the Community Contribution wizard now redact baseboard serial numbers by default (e.g. `5C******67`).
  - Added an opt-in `-WithSerial` flag for diagnostic scenarios where the full serial is intentionally needed.

### 🔧 Hardware & BIOS Control Improvements

- **GPU Power Presets Zero Peak Temperature Bug (Fixes #226, PR #226):**
  - `BiosCtl.SetGpuPower` no longer overwrites the BIOS peak temperature byte with 0. Preserves the currently set BIOS threshold or falls back to OEM default 87 °C (`0x57`).
- **Manual Fan Levels Pre-call for 8BAC / 2023+ Laptops (Fixes #223, PR #223):**
  - `BiosCtl.SetFanLevel` now issues a fan count query (type `0x10`, 1-byte input) prior to writing `0x2E` levels. This arms manual fan control on boards where BIOS acknowledges writes but ignores them otherwise.
- **Shared Heat Pipe Fan Program Option (`FanProgramSharedTemperature`) (PR #225):**
  - Added `<FanProgramSharedTemperature>false</FanProgramSharedTemperature>` option in `OmenMon.xml` and CLI. When enabled, both fans follow `max(CPU, GPU)` for laptops with shared heat pipes/fins, reducing GPU peak temperatures by ~5 °C under asymmetrical GPU load.
- **Thermal Policy V1 Boot Fan Mode Alias (`Boot`) (Fixes #230):**
  - Added named `Boot` mode (`0x01`) to `BiosData.FanMode` and CLI parser (`-Bios FanMode=Boot`) to allow restoring factory boot acoustics without rebooting Windows.
- **Expanded BIOS Fan Table Capacity to 42 Levels (Fixes #231):**
  - Expanded `BiosData.FanTable` array capacity and `SizeConst` from 14 to 42 entries (the full 128-byte BIOS payload limit). Replaced misleading syntax error with descriptive boundary validation.
- **Diagnostic Register Plausibility Warnings (Fixes #229, #235):**
  - `-Probe` and `-Diag` reports now flag implausible register readings (e.g. legacy LE16 tachometers > 8000 RPM, CPU temp < 15 °C or > 115 °C, GPU temp = 1 °C on 8BC2), explaining relocated registers on 2023+ architectures.
